# cloud-to-local-chat

Экспериментальная утилита переноса переписки ChatGPT в локальный чат Codex. Старые вопрос и ответ отображаются в ленте, а историю можно продолжать.

## Подготовка истории и картинок

Можно передать готовый JSON или получить один чат по ссылке через `--chat-url`. При первом получении открывается установленный обычный Google Chrome с отдельным профилем `data/browser-profile`, без управления скриптом и порта отладки. Войдите в ChatGPT: скрипт ждёт сохранения сессии на диске и создаёт согласованный SQLite-снимок cookies и копию `Local State` в `data/browser-profile/background`. С этого отдельного рабочего профиля история и оригиналы изображений получаются в фоне, прогресс выводится в терминал. Закрывать рабочий Chrome не нужно. Вход и CAPTCHA выполняет пользователь. Расширение Chrome и инструменты агента не нужны.

Сессия входа сохраняется в отдельном профиле для следующих запусков. Этот профиль даёт доступ к аккаунту: не публикуйте его и не передавайте другим людям. Он находится в исключённой из Git папке `data/`; на диске устанавливаются права доступа только для владельца. Скрипт не использует и не копирует основной профиль Chrome. После первого успешного получения последующие запуски используют сохранённую сессию скрыто. Если она истекла, завершите скрипт, откройте обычный Chrome с тем же `--user-data-dir` и повторите вход. Google может блокировать вход в управляемом браузере, поэтому этап входа выполняется отдельно; доступ сайта из фонового браузера всё равно требует проверки.

После чтения сессии скрипт запрашивает историю и ссылки на оригиналы авторизованными HTTP-запросами; веб-страница чата в фоне не открывается. На macOS используется штатная связка ключей Chrome, чтобы прочитать сохранённый вход. Токен не выводится и не сохраняется отдельным файлом, серверу изображений он не передаётся.

Получение использует внутренний ответ сайта с текущей веткой разговора и внутренний адрес скачивания файлов. Формат может измениться. Вызовы генератора и индикаторы времени размышления не добавляются как отдельные ответы; видимые результаты генерации и текстовые ответы сохраняются. Неподдерживаемое содержимое, отдельные рассуждения, отсутствующие оригиналы изображений и незавершённые обмены останавливают перенос. Для подтверждённо недоступных документов сохраняются карточки вложений, а ограничение фиксируется в метаданных. Пропущенные изображения не заменяются миниатюрами. Ошибки входа, сети и временные HTTP-ошибки останавливают операцию; автоматического обхода проверок сайта нет.

Вложения пользователя указываются как `localImage` с абсолютным путём, картинки ассистента — списком `images` у `agentMessage`. Файлы вне папки проекта копируются в её `images/` без изменений. Картинки ассистента отображаются в ответах через Markdown.

Обычный `read_thread` может пропускать сгенерированные картинки и ответы. Такой источник нужно дополнить перед переносом. Прежние ответы и изображения не генерируются заново.

## Запуск

Нужны Python 3.10+, обычный Google Chrome и установленный `codex` с поддержкой используемого протокола. Поддержка импорта проверена на версии `0.162.0-alpha.17.2`; совместимость других версий не установлена. Для получения из браузера установите Playwright (отдельный тестовый Chromium не нужен):

```sh
python3 -m pip install -r requirements.txt
python3 cloud_to_local_chat.py \
  --chat-url 'https://chatgpt.com/c/ИДЕНТИФИКАТОР' \
  --project-root '/существующая/папка/проекта' \
  --apply
```

Папка назначения обязательна и должна существовать. Скрипт не выбирает её по облачному проекту и не создаёт подпапок с его названием. Если папка уже принадлежит локальному проекту, используется этот проект; иначе создаётся запись проекта с этой папкой. Название по умолчанию — имя папки, его можно задать через `--project-name`. При нескольких проектах на одной папке операция останавливается. История и скачанные файлы остаются в `data/cloud-<id>/`; повторное получение поверх существующего `source.json` отклоняется. Для переноса уже скачанного чата передайте этот файл как обычный источник.

Без `--apply` облачный режим всё равно требует входа, получает историю и сохраняет файлы, но не создаёт локальный чат. Запуск с готовым файлом не требует Playwright.

Положите подготовленную историю в `data/source.json`. Предварительная проверка ничего не создаёт:

```sh
python3 cloud_to_local_chat.py data/source.json \
  --project-root /absolute/path/to/local-project \
  --project-name 'Название проекта'
```

Для импорта добавьте `--apply`. Для изолированного теста используйте `--codex-home /absolute/path/to/test-home` и `--data-dir /absolute/path/to/private-data`.

В каталоге данных сохраняются квитанция с идентификаторами и контрольными суммами файлов, резервная копия нового журнала, снимок строки индекса перед восстановлением дат и резервная копия реестра проектов. Повторный запуск с тем же источником, папкой проекта и хранилищем отклоняется, если квитанция уже существует. При ошибке изучите квитанцию; повторять запуск вслепую не следует. Исходный облачный чат не изменяется.

## Даты и локальные проекты

Для последовательного переноса всех собственных чатов проекта укажите его облачный идентификатор и существующую папку:

```sh
python3 cloud_to_local_chat.py --project-id g-p-ИДЕНТИФИКАТОР \
  --project-root '/существующая/папка/проекта' --apply
```

Список проходит все страницы. Для каждого чата в `chats/<id>/` сохраняется полный ответ сервера `raw.json`, подготовленный `source.json` и оригиналы изображений. `import-report.json` обновляется после каждого шага и содержит идентификатор локальной копии, ошибки и заявки на привязку. Повторный запуск пропускает записи со статусом `prepared` или `existing`; для частичного сбоя квитанция препятствует слепому созданию дубля. Успех одной переписки не означает успех всего проекта: проверяйте итоговые счётчики и ошибки в отчёте.

Карточки размышлений и поиска остаются в `raw.json`, а их идентификаторы отмечаются в `processCardsStoredInRaw`; в локальный диалог добавляются вопросы и ответы. Последний вопрос без ответа сохраняется без выдуманного ответа. Голосовой ввод и голосовые диалоги переносятся по сохранённым текстовым расшифровкам пользователя и ChatGPT, с исходными датами. Ссылки на звук остаются в `raw.json`, а сообщения с расшифровками отмечаются в `provenance.voiceTranscripts`; аудиофайлы не скачиваются. Явно пустая расшифровка сохраняется пустой, с датой и следующим ответом; это отмечается только в `emptyTranscription`, служебный текст в сообщение не добавляется. Голосовое сообщение без поля расшифровки и видео останавливают перенос, чтобы содержимое не потерялось незаметно. Файловые вложения скачиваются без изменения байтов в `chats/<id>/files/<sha256>/<исходное имя>` и отображаются карточками в исходном сообщении. Привязка и статус записываются в `provenance.fileAttachments`. При HTTP 404 или 410 на оригинал утилита автоматически сохраняет карточку со ссылкой на отсутствующий файл: имя видно, открыть содержимое нельзя. Пустые PDF или подписи на диске не создаются, служебные пояснения в переписку не добавляются. Недоступные файлы отмечаются статусом `unavailable` и отдельно перечисляются в отчёте (`unavailableFileAttachments`, `unavailableFileCount`, `attachmentsComplete: false`); их оригиналы не считаются сохранёнными. Ошибки входа, временные сетевые ошибки, несовпадение размера и ответ вместо PDF останавливают перенос; полный исходник остаётся в `raw.json`. Внутренние превью страниц из `file_search` остаются в исходнике и не добавляются в ответы как сгенерированные картинки. При переносе в другой локальный проект документы копируются в его папку, а пути карточек обновляются. Для изображений в контексте задаётся `detail: original`, чтобы Codex не уменьшал их при добавлении истории. Исходные файлы отдельно сохраняются без изменений.

`thread.createdAt` и `thread.updatedAt` должны содержать исходные Unix-времена в секундах. Для обменов нужен `startedAt`; неизвестный `completedAt` допускается оставить `null`. При неизвестном времени отдельного ответа событие отображения использует известное начало обмена, а не момент переноса. Это отметка обмена, не восстановленная точная секунда создания картинки.

Приложение может менять дату последнего обновления (`updatedAt`) при открытии локального чата. Исходная дата создания и даты обменов сохраняются; исходное время обновления отдельно записано в источнике и квитанции. Если в импортированном чате появились новые сообщения, восстановление дат отказывается перезаписывать метаданные.

Служебное `recency_at` сохраняет время добавления локальной копии, чтобы старые переписки попадали в начальную выдачу боковой панели. Это поле отдельно от исходных дат создания, обновления и сообщений; восстановление исходных дат его не изменяет.

У приложения также есть отдельный каталог боковой панели в `~/.codex/sqlite/codex.db` либо `codex-dev.db`. При завершении привязок с закрытым приложением утилита делает резервную копию этой базы и сбрасывает только три отметки синхронизации строки `host_id=local`, чтобы приложение при запуске пересканировало старые импортированные чаты. Записи каталога, другие хосты, переписки и даты не удаляются. При наличии обеих баз автоматический выбор отклоняется. Повторный запрос уже сброшенных отметок ничего не меняет.

Для отдельного запроса пересинхронизации:

```sh
python3 cloud_to_local_chat.py --refresh-catalog --wait-for-app-exit --apply
```

Запустите команду из независимого терминала, полностью закройте ChatGPT/Codex, дождитесь результата `requested: true` и откройте приложение снова. Это запрос на пересинхронизацию; успешная запись отметок сама по себе не подтверждает обновление боковой панели.

Открытое приложение перезаписывает реестр проектов из памяти. Поэтому при импорте в действующее хранилище создаётся заявка `register-<threadId>.json`. Чтобы завершить привязку, полностью закройте приложение и выполните:

```sh
python3 cloud_to_local_chat.py \
  --register-request /absolute/path/register-first.json /absolute/path/register-second.json \
  --data-dir /absolute/path/to/private-data --apply
```

Можно запустить эту команду из независимого терминала заранее с `--wait-for-app-exit`: она дождётся закрытия приложения до 15 минут, запишет обе привязки и завершится. Затем откройте приложение снова. Команда сама не закрывает и не перезапускает приложение. Остальные проекты сохраняются.

## Ограничения

- Утилита использует внутренний формат истории Codex. Совместимость с другими версиями приложения не гарантируется.
- Не открывайте создаваемый чат во время импорта: одновременная работа приложения с ним не проверена.
- Восстановление после частичного сбоя требует анализа квитанции и резервных копий. Автоматического удаления созданного чата при сбое нет.

## Проверки

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

Модульные проверки используют вымышленные данные и не обращаются к приложению, аккаунту или настоящим чатам.
